# Reusing classified evidence across features

**Design proposal.** A new reader question about facts we already publish should usually require one bounded read query and a presentation change. For example, an official's profile starts from a member's recorded casts and filters by issues the reader follows. An issue page starts from the same issue assignments and follows the same casts back to officials. Both should return the identical vote question, cast, revision and citation. Changing the classifier or adding another issue should leave both readers usable.

## What already works and where coupling remains

Editors maintain issue IDs, definitions, policy areas and examples in `config/issues.json`. For each published release, PostgreSQL stores names and definitions for the issue IDs present on its records in `release_issues`, with examples in child tables. The public views `bill_issues` and `vote_issues` associate tracked issue IDs with evidence revisions. For example, the existing definition of `middle-east-conflicts` explicitly includes Iran. The existing issue reader queries typed published votes, bills and sponsors in one release snapshot. Existing relationship records serve a narrower purpose. Their pair finder looks for bill references in a speaker's statement and requires a corresponding sponsorship or member cast. This protects attribution. A survey question has no legislator cast of its own. Give polling a producer with its own validation when that feature is selected. [Issue catalog](../../config/issues.json), [issue reader](../../src/CivicLens.PublicApi/Issues/IssueStore.cs), [pair finder](../../src/CivicLens.Application/Relationships/RelationshipPairFinder.cs) and [current relationship kinds](../../src/CivicLens.Core/Relationships/RelationshipRecordKind.cs).

The trial scripts deliberately pin examples. One names two Senate roll-call pairs. Another ranks lexical sections and adds votes linked to the leading bill. Keep case IDs, expected answers, model names and retrieval settings in experiments and evaluation inputs. Production consumers should request facts by issue, official, predicate and date. [Vote pair study](experiments/compare-senate-votes.py) and [retrieval trial](experiments/evidence-trials/text-trials.py).

## Can a versioned table replace the repeated definitions?

Yes. Publication currently copies the name, definition and ordered inclusion and exclusion examples for every issue present on the release's records. Two releases with the same wording can have different bill and vote counts. A configured issue with no record in a release can be absent altogether. An older ID missing from the authoring catalog can appear with its ID as its name and no definition. [Release membership](../../src/CivicLens.Application/Publication/ReleaseFacets.cs), [missing-definition handling](../../src/CivicLens.Application/Publication/PublicationCatalog.cs), [release writer](../../src/CivicLens.Infrastructure/Publication/ReleaseNameRows.cs) and [issue counts](../../src/CivicLens.Infrastructure/Publication/ReleaseIssueCounts.cs).

**Next-phase design.** Store each distinct public definition for an issue once in an immutable versioned table, including its display name and ordered examples. Keep a small row per release and issue with a reference to that exact version and the release-specific figures. Two releases can share one definition while their counts change. A definition edit creates a version. The existing public view can join through the reference, so the API and issue pages can keep their contracts. The publication store already uses a comparable pattern for correction histories. [Correction history storage](../../src/CivicLens.Infrastructure/Publication/CorrectionHistoryCopies.cs).

**Authoring and classification.** Keep `config/issues.json` as the editing source so definition changes go through Git review. Publication owns the versioned public tables. Classifiers already record a content-derived revision of the full rubric, including its policy areas. Preserve that identity for reproducing classifications. A revision of the public wording alone cannot reconstruct which other issues a classifier considered. [Rubric identity](../../src/CivicLens.Application/Issues/IssueConfigurationRevision.cs).

For migration, derive public versions from the values of each retained release, including nulls and ordered examples. Pin the version and membership in the release commit transaction. Preserve release-specific counts and their unknown states. Compare the old and new public answers for every retained release, including activation and rollback, before switching readers. The current copies are simple and protect history already. Measure write volume and indexed read cost on a representative copy before scheduling migration. The next phase owns migration and rollout.

A [read-only PostgreSQL measurement](experiments/measure-issue-definition-reuse.sql) on November 19, 2026 found 192 release-issue rows across retained releases 1424 through 1435. All 12 contained the same 16 public definitions, including their display names and ordered examples. The counts were also unchanged for each issue across this window. References could represent these 192 copies of the wording with 16 definition versions. This measures repetition. It does not measure a latency or storage bottleneck.

The [versioned-table experiment](experiments/versioned-issue-definitions.sql) uses three synthetic releases. The first two share one wording with bill counts of three and five. The third uses edited wording. Reading the first again restores the original wording and count, keeps an unknown count and missing definition on a legacy ID, and omits a configured issue with no member record. This checks join semantics only. Run it with `sqlite3 -bail -header -column :memory: < docs/post-r68/experiments/versioned-issue-definitions.sql`.

## Proposed interface between producers and readers

| Responsibility | What crosses the boundary | Who owns its meaning |
|---|---|---|
| Evidence identity | Record kind, stable ID, exact revision and a citation locator. Use the unit being classified, such as a provision in a particular bill edition, a quoted span or one survey question in a specific wave. Carry event date, evidence availability and release identity separately. | The source's feature owns parsing, identifiers and validation. A missing date stays unknown. |
| Issue assignment | Evidence reference, issue ID, catalog version, relevance grade, reason and cited passage. A single evidence item may have several issues. Keep the method and model or rule version, any confidence estimate and review decision on the assignment revision. | The classifier proposes an assignment. Existing source-validation and review rules govern eligibility. Reclassifying against a revised definition creates a new result. |
| Typed relationship | A named, directed fact with permitted endpoint kinds, exact endpoint revisions and supporting evidence. A recorded cast connects a member to a roll call. A reviewed comparison can connect a survey question to a policy decision. Each has a different evidence requirement. | The feature that establishes the fact owns its checks and authority. Give a new predicate a definition and eligible evidence before exposing it. |
| Public consumption | Publication chooses eligible revisions. PublicApi composes typed views in one release and returns bounded, feature-specific results with citations and coverage. The UI displays the supplied meaning and reason for selection. Private pilot data stays in the review workflow. | Publication owns release membership and corrections. PublicApi owns the read query. PublicWeb owns presentation. [Publication](../architecture/publication.md) and [public site contracts](../architecture/public-site.md#storage-and-contracts). |

**Recommendation for the first pilot.** Reuse feature-owned tables, typed keys and read views with a small shared identity and citation convention. Putting every relation in one generic edge table would simplify traversal but require separate checks for valid endpoint combinations and source-specific facts. Letting each page classify on demand would duplicate work and allow two pages to disagree on the same release. The physical schema and any new public API remain decisions for the owner. The private pilot can exercise the boundary with two read projections before proposing either.

Additive fields should allow older consumers to keep reading their supported facts. A consumer that does not understand a new predicate must omit its interpretation or show an explicit unavailable state. Changing predicate meaning or a field's unit requires a new version. Bind every derived finding to its input revisions. Reevaluate or suppress it when a dependency changes or is withdrawn, including on cached pages. Keep the serving path within one release and apply evidence availability cutoffs to historical comparisons. [Delivery trial](delivery.md#acceptance-trial).

## How much work should an extension take?

- **Another issue on existing evidence.** Add a versioned definition and positive and negative examples, then evaluate on unseen families. Audit candidate coverage. The existing bill selector limits candidates by policy area, so a secondary provision in an omnibus bill can be missed before scoring. A domain-wide fix belongs at that selector. Avoid an issue-name switch in the reviewer, API or page. [Bill issue choice](../../src/CivicLens.Application/Issues/BillIssueChoice.cs).
- **Another feature on existing facts.** Add a query, response mapping and UI. Deduplicate on the identity of the thing being counted. A member's one cast can match several followed issues. Authorization, publication eligibility, evidence checks and classification stay with their existing owners.
- **Another evidence type or kind of inference.** Add the necessary ingestion, version binding, validation, evaluation and publication mapping once. A poll needs exact wording, answers, population, geography, field dates, release date, sample and survey-method disclosures. A national distribution cannot establish district opinion. Same-issue membership can propose comparison candidates. A directional interpretation also needs a matching policy choice, scope, timing and motion polarity. An undated or materially different question can still supply labeled context. [Polling disclosure standards](https://aapor.org/standards-and-ethics/disclosure-standards/).

Test three levels of positive relevance, from incidental mention through material implementation to a direct policy decision. Record unrelated and unassessed separately. Read the operative passage. An eligibility rule may directly affect household costs. Keep evidence relevance, confidence in classification, reader-selected interests, issue salience in surveys and the distribution of survey answers distinct. Explicit follows can reorder a private view while the public factual result stays identical for all readers. Keep reader preferences out of shared release rows and public caches.

## Features built from those relations

| Reader question | Joins that supply the answer | Additional evidence or check |
|---|---|---|
| What has this official actually done on my issues? | Followed issue → classified provision or action → exact decision → member and role | Keep sponsors, casts and executive signatures distinct. Rank by directness and explain each inclusion. |
| Which officials acted on the same problem in different ways? | Issue + affected group → provisions grouped by mechanism → sponsors and member casts | A tax credit and a grant can address the same problem. Their beneficiaries and legal effects need separate evidence. |
| Which promise is coming due, and what has been delivered? | Quoted commitment → responsible office → due date → implementation event → reported measure | Preserve the deadline's anchor and each stage. Report the last source checked and the gap when no completion evidence was found. |
| What changed for people eligible for this benefit? | Population + eligibility condition → old and new provision revisions → adoption or effective date | Compare the actual qualification. A renumbered clause can survive and an unchanged number can acquire a different subject. |
| Do several public claims rely on independent evidence? | Claim revisions → cited observations → originating source | Collapse citations that repeat one agency release. An unresolved source lineage leaves the independence count uncertain. |
| How does a decision compare with opinion on this issue? | Issue → poll question and response distribution. Issue → action and vote. Join the two through an assessed comparison. | Preserve the precise population and question on each result. Distinguish a contemporaneous poll from later opinion and an opinion about authority from support for a particular resolution. |
| Which findings on followed issues need another look? | Revised or withdrawn source → dependent finding revisions → affected issues | Show one material change per finding with the prior and current citations when eligible. Keep reader state private. |

Existing action, vote and issue data can already support a basic official activity view. Provision-level classification, reliable policy mechanisms, commitment tracking, poll questions and source lineage each need producers before joins can answer those parts. These are candidate features for later decisions. The first private pilot still ends at its agreed handback.

## Offline interface check

The [SQLite example](experiments/reuse-issue-facts.sql) builds one activity view from three real House roll calls and six selected casts by Reps. Thomas Massie and Alma Adams. The original Clerk XML digests identify the vote inputs. The issue memberships and pair assessments are analyst-supplied test inputs. Two Iran votes each receive two overlapping issue labels. The third vote, on S. 146, supplies the artificial intelligence case. [House roll 84](https://clerk.house.gov/Votes/202684), [House roll 85](https://clerk.house.gov/Votes/202685) and [House roll 104](https://clerk.house.gov/Votes/2025104).

In the profile query, two followed topics returned two distinct votes for Massie. In the issue query, the same view returned both members' casts on S. 146. A third query added one CBS/YouGov poll question and two comparison judgments without modifying either existing view. The authorization question supplied context for the withdrawal resolution. The terrorism resolution shared the topic only. Neither motion was a sufficient match for a directional comparison. A share of actions aligned with the public is therefore undefined. [Survey, question 7](https://d3nkl3psvxxpe9.cloudfront.net/documents/cbsnews_20260303.pdf) and [withdrawal resolution text](https://www.govinfo.gov/content/pkg/BILLS-119hconres38ih/html/BILLS-119hconres38ih.htm).

```sh
sqlite3 -bail -header -column :memory: < docs/post-r68/experiments/reuse-issue-facts.sql
```

Switching the request to Adams and artificial intelligence returned the same cast and source digest through both readers. This small check establishes query reuse on fixed inputs. Classifier accuracy, production query costs and release lifecycle behavior remain unmeasured. In the private pilot, add another bill family without editing the queries. Exercise a multi-issue duplicate, an unsupported link and a stale review in the private workflow. The later poll and public-route trials own unassessed poll comparisons and the propagation of withdrawals. Track which extension needed new producer code, any changes to existing consumers, per-issue precision and recall, and unsupported attributions among interpreted links.
