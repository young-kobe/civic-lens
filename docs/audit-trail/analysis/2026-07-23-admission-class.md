# 2026-07-23 — `corpus.documents.admission_class`: official record vs. sampled discourse

`corpus.documents` now carries an `admission_class` column (`corpus.admission_class` enum: `'sampled'` | `'official_record'`) that distinguishes the existing 30-day discourse sample from a new class of X posts admitted purely because their author is a tracked, currently-active official — regardless of age. This is Postgres redesign Phase 8 prep (owner-approved 2026-07-23; plan `docs/todos/pg-redesign.md`), landed alongside the ingestion-side backfill command — see `docs/audit-trail/ingestion/2026-07-23-backfill-officials.md` for the Go half that populates the deep history this admission path now lets through.

## What shipped

- **`data/pg-migrations/0003_admission_class.sql`**: `CREATE TYPE corpus.admission_class AS ENUM ('sampled', 'official_record')`, then `ALTER TABLE corpus.documents ADD COLUMN admission_class corpus.admission_class NOT NULL DEFAULT 'sampled'` — the single `ADD COLUMN ... DEFAULT` backfills every pre-existing row in the same statement, no separate `UPDATE` needed. Applies cleanly on top of `0001_north_star.sql` + `0002_entity_registry_seed.sql`; not self-idempotent (same one-shot-apply convention as `0001`/`0002` — `CREATE TYPE` has no `IF NOT EXISTS` in Postgres), tracked instead by the Go migration runner's `ops.schema_migrations` ledger.
- **`analysis/src/etl/documents.py`**: X-post admission now resolves the author's `corpus.authors.author_id` *up front* (in `_gather_x_candidates`, not deferred to insert time as before), because the admission decision itself depends on it. `_resolve_official_author_ids` joins `corpus.author_profiles.entity_id -> corpus.entities` and selects authors whose linked entity is `kind='official' AND active=true`. An author with a matching row gets `_admit_x_official` — political-content check only, no recency gate at all — instead of the ordinary `_admit_x` (recency + political). Every other X post, and all news/reddit docs, keep the existing gate and the table's `'sampled'` default. `_insert_x_candidates` splits admitted candidates into `sampled` and `official_record` groups and enforces two independent caps: the pre-existing per-domain window cap for `sampled`, and a new lifetime (not per-window) cap for `official_record`, `select_within_domain_cap` reused with `author_id` as the grouping key instead of `domain_or_subreddit`.
- **`analysis/src/etl/constants.py`**: `ADMISSION_SAMPLED`, `ADMISSION_OFFICIAL_RECORD` (the two enum values, string-typed to match psycopg's enum cast pattern used elsewhere in this module); `OFFICIAL_RECORD_PER_AUTHOR_CAP = 200` (lifetime cap per author — a tuning knob, not derived from data, flagged for owner review below); `ETL_VERSION` bumped `pg-1` -> `pg-2`.
- **`docs/DATABASE_SCHEMA.md`**: `corpus.admission_class` enum documented alongside the existing enum list; `corpus.documents.admission_class` column documented in the table's column reference.
- **Test coverage**: `analysis/tests/test_etl_documents.py` gained `_admit_x_official` unit tests (bypasses recency entirely, still rejects non-political text) and four gated integration tests — an active official's 100-day-old post is admitted as `official_record`; the identical post from an unlinked author is rejected as stale (`skipped_old`); an *inactive* official's entity does not grant the bypass; the per-author cap drops the oldest post first once more than `OFFICIAL_RECORD_PER_AUTHOR_CAP` accumulate. New `analysis/tests/test_migration_admission_class.py` exercises `0003_admission_class.sql` directly on top of `0001`+`0002` (column shape, pre-existing rows backfilled to `'sampled'`, new rows default without specifying the column, not self-idempotent). `analysis/tests/pg_fixture.py`'s `reset_schema` now always applies `0003` (after the optional `0002` seed) so every gated module's baseline schema tracks the latest migration.

## Design notes (owner-facing)

- **Two-pass convergence, by construction rather than by a special "recheck" step.** `_gather_x_candidates` selects from `raw.x_posts` via `WHERE NOT EXISTS (... corpus.documents ...)` — a rejected row is simply never written to `corpus.documents`, so it remains eligible on every subsequent ETL run. This means an official's post rejected today (author not yet linked via `account_tier.py`/`corpus.author_profiles`) is automatically re-considered, and admitted as `official_record`, the moment that linkage exists — no queue, no retry flag, no re-ingestion. Verified live this task: seeded a 100-day-old post from an author with no `author_profiles` row -> rejected as stale on pass 1; inserted the `author_profiles` row (simulating `account_tier.py`) -> the same row, unchanged, was admitted as `official_record` on pass 2.
- **Stage ordering matters and is pre-existing, not new.** `account_tier.py` (which writes `author_profiles`) runs later in the pipeline than the ETL stage (see `job_runner.py`'s stage order). A freshly-ingested official's posts will not get the bypass on the very first ETL pass after ingestion — they get it on the next one, after `account_tier` has run. This is the same "eventually consistent within one pipeline cycle" pattern the rest of the author-tier system already relies on.
- **`OFFICIAL_RECORD_PER_AUTHOR_CAP = 200` is a tuning knob, not a derived value** — flagged in the constants module for Kobe to revisit once real per-official volume is visible against production data (see follow-ups).

## Why

- General discourse sampling is deliberately time-boxed (30-day window) so the corpus reflects *current* sampled conversation, not an ever-growing archive — but an official's own public statements are public record regardless of when they were posted, and Phase 8's officials-backfill command (see the ingestion entry) exists specifically to pull that older history in. Without an admission-class distinction, the backfilled posts would either be silently dropped by the existing recency gate (defeating the backfill) or would quietly violate the "current sample" framing other 'sampled' docs rely on. `admission_class` makes the distinction structural and queryable rather than inferred from `published_at` after the fact.
- The lifetime per-author cap exists because bypassing recency entirely, with no ceiling, would let one prolific official's account dominate corpus composition — the same skew concern that motivated the pre-existing per-domain cap for ordinary discourse.
