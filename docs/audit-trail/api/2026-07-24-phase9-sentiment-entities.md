# 2026-07-24 — Phase 9 workstream A: sentiment panel + entity drill-downs (strictly live)

The tone/sentiment panel and the two entity drill-down endpoints now aggregate `corpus.*`/`analysis.*` live at request time, per the Phase 9 strictly-live architecture (`docs/audit-trail/analysis/2026-07-24-phase9-prewave.md`). No caching, no rollup table — every request runs fresh SQL against the current corpus.

## What shipped

- **`analysis/src/api/queries/sentiment.py`** — `get_sentiment_panel(window=None, date_from=None, date_to=None)`: resolves the time scope via `queries/base.py::resolve_time_range` (a preset `window`/`'all'` XOR an explicit `date_from`/`date_to` — historical data stays queryable forever, owner decision), then computes net tone, the strong/mild/neutral intensity distribution, platform/topic/time-of-day/day-of-week splits, the news/officials/general-public tier split (via `corpus.author_profiles.tier`), and per-entity stance aggregates merging `analysis.favorability_stances` + `analysis.target_mentions` (joined to `corpus.entities`; unresolved mentions bucket under a `catch_all_key="unresolved"` cell rather than vanishing). Denominators count `analysis.runs` rows (`task='text', is_current, status='done'`), not result rows — a trivial-content doc (no `sentiment_results` row) is counted in `overview.totalAnalyzed`/`trivialContentDocs`, never folded into a fake neutral. Bot exclusion: any doc whose author's `analysis.author_bot_scores.score >= BOT_SCORE_AUTHOR_EXCLUSION` is excluded from every aggregate (`overview.excludedBotDocs` reports the count). Topic resolution prefers the doc's dominant `target_mentions.topic`; a small local `TOPIC_KEYWORDS` title-keyword map (module-local, a subset of the read-only legacy `reporting/aggregators/constants.py` list) is the fallback.
- **`analysis/src/api/queries/entities.py`** — `get_entity_posts(entity_id, window=None, date_from=None, date_to=None, page=1)`: paginated (20/page) docs mentioning and/or authored by an entity, tagged `relation` (`mentions`/`authored_by`/`both`), newest first. `get_entity_profile(entity_id)`: an unconditionally ALL-TIME profile (no window parameter at all) — analyzed doc counts split sampled/official_record, stance-received (`target_mentions`, entity as target) vs stance-expressed (`favorability_stances` on docs the entity itself authored/published), propaganda rate, first/last activity, and a monthly activity timeline. Both read the entity's own doc history through whichever join applies to its kind: `corpus.author_profiles.entity_id` (officials/collectives), `corpus.news_articles.outlet_entity_id` (outlets), `corpus.reddit_posts.subreddit_entity_id` (subreddits).
- **`analysis/src/api/models/sentiment.py`**, **`analysis/src/api/models/entities.py`** — CamelModel response shapes: `SentimentPanelResponse`, `EntityPostsResponse`/`EntityPostRow` (extends `SampleDocModel` with `relation`), `EntityProfileResponse`. Every aggregate response (`SentimentPanelResponse`, `EntityProfileResponse`) embeds a `RangeMeta` (from the updated `models/common.py`): resolved `start`/`end` (null = unbounded), `sampledDocCount`/`officialRecordDocCount`, and the distinct `modelIds` among contributing runs — the honesty block flagging when a wide range spans a model/prompt change. `entity-profile`'s `range` always has null bounds (all-time by construction).
- **`analysis/src/api/routers/sentiment.py`**, **`analysis/src/api/routers/entities.py`** — thin `APIRouter`s (not mounted — a later workstream registers them). `GET /sentiment` takes `window` (default `'30d'` when nothing given) XOR `from`/`to`; `GET /entity-posts` takes the same three, defaulting to `window='all'` (unbounded) when none given, since an official's `official_record` history can predate every preset window; `GET /entity-profile/{entity_id}` takes no time param at all. All three map a query-layer `ValueError` to 404 (unknown `entity_id`) or 400 (bad range).
- **Tests**: `analysis/tests/test_api_queries_sentiment.py`, `analysis/tests/test_api_queries_entities.py` (pure row-helper tests + gated integration tests seeding through `pg_fixture`), `analysis/tests/contract/test_sentiment_contract.py`, `analysis/tests/contract/test_entities_contract.py` (gated, mount the routers standalone via `TestClient`, snapshot the JSON shape).

## Why

- **Strictly-live, no `serving` schema** (see the analysis-layer prewave entry) — these are the first panel queries built against that decision; `queries/base.py`/`constants.py`/`models/common.py` were pre-built scaffolding, this workstream is their first consumer.
- **Historical data stays queryable forever, EVERY panel** (owner decision, mid-task correction 2026-07-24): windows scope aggregate denominators, never document existence. An elected official's `official_record` X-post history can run back years past every preset window (`0003_admission_class.sql`); a drill-down or profile that silently dropped it because of a hardcoded 90-day ceiling would misrepresent an active official as newly-appeared or dropped. `resolve_time_range` makes `'all'` and an explicit `date_from`/`date_to` first-class options everywhere a window appears, not just a documented workaround.
- **RangeMeta is the disclosure mechanism for that same freedom**: once a caller can ask for a multi-year range, the aggregate might silently span a Gemini model swap, a prompt-version bump, or an `admission_class` regime change (0003 shipped 2026-07-23 — everything before it is `sampled` by default backfill). Surfacing `modelIds` and the two admission-basis counts on every aggregate response lets the UI label that instead of presenting one falsely-continuous series.
- **Denominator = analysis.runs, not result rows**: `analysis/src/engine/text.py`'s trivial-content path (git history 2026-07-23, "remove placeholder neutral confidence") already established that a trivial doc gets a `done` run with no `sentiment_results` row. A panel that joined `sentiment_results` for its total would silently undercount runs, and one that defaulted a missing join to "neutral" would fabricate a rating no model produced.

## Judgment calls

- **Scope simplification vs. the pre-redesign `reporting/aggregators/sentiment/*` reference**: that package's engagement-weighted nets, same/cross-party `expressed_alignment` control, per-narrative received-tone breakdowns, and sampled-author follower-floor consolidation depend on the retired `entity_registry` YAML + `account_profiles` machinery this redesign removed. They are not reproduced here — the new panel's tier split and per-entity stance aggregates are built directly from `corpus.entities`/`corpus.author_profiles`, a materially simpler (and DB-native) model. Flagged as a scope reduction, not an oversight.
- **Time-of-day is literal** (`Morning`/`Afternoon`/`Evening`/`Night` by `published_at` hour), replacing the old package's `TimeWindowSentiment` (which was actually an age-since-published bucket mislabeled "time window"). The task spec asked for "time-of-day" explicitly; this reading matches that literally rather than porting the old field's odd semantics.
- **`analyzed_doc_counts` on `entity-profile`** covers only the entity's own authored/published docs (not docs merely mentioning it) — "an official's doc history, split by admission basis" reads most naturally as their own posts, keeping it distinct from the drill-down's broader mentions-or-authored union.
- **Net-tone score is a simple pooled (positive − negative)/volume**, not the pre-redesign package's per-tier-balanced mean (which weighted news/officials/public equally so a high-volume tier couldn't skew the headline). Simpler and defensible given the panel already exposes the tier split separately for that comparison; noted as a follow-up if Kobe wants the balancing back.
