# 2026-07-24 — Phase 9 final workstream: review service, ops surface, doc drill-down, app wiring

The last Phase 9 workstream: a Postgres-native review service, the two ops/freshness endpoints, the universal document drill-down, and the wiring that mounts every panel router (this workstream's plus the three parallel ones: `docs/audit-trail/api/2026-07-24-phase9-sentiment-entities.md`, `-bots-outlets-movers.md`, `-narratives-propaganda.md`) into one servable `FastAPI` app. `analysis/src/reporting/review.py` and the old `api/routers/data.py`/`api/cache_utils.py` are the last SQLite/cache-era pieces this wave touches — `reporting/review.py` is left running untouched (it dies at Phase 11 alongside `job_runner.py`), while `data.py`/`cache_utils.py` are deleted outright since nothing else in the strictly-live app needs a cache layer.

## What shipped

- **`analysis/src/review/`** (`__init__.py`, `constants.py`, `service.py`) — the review service, module-level functions (matching every other Phase 9 query module, not the old class shape): `get_queue(task, ...)` — unreviewed current runs (`analysis.runs` `is_current AND status='done'`, `LEFT JOIN analysis.evals ON run_id` `IS NULL`), lowest-confidence first, joined to `corpus.documents` for preview text/`source_url`/`admission_class`; `submit(run_id, verdict, ...)` — `INSERT ... ON CONFLICT (run_id) DO UPDATE` into `analysis.evals` (a verdict on ONE run, correctable), and when `is_golden`, mints/refreshes the `(doc_id, task)` `analysis.golden_labels` row via `ON CONFLICT (doc_id, task) DO UPDATE` in the SAME transaction; `get_stats()`/`get_public_accuracy()` — per-task counts and agreement, the latter suppressing `accuracyPct` below `MIN_PUBLIC_REVIEW_N` (ported verbatim from the old `reporting/review.py`, now in `review/constants.py`).
- **`api/routers/review.py`** rewritten against the new service. Task filter is now the `analysis.task` enum (`bot`/`text`/`targets`/`propaganda`/`claims`/`citations`/`account_tier`) — a deliberate contract change from the old `sentiment`/`favorability`/`bot_detection`/`claims`/`propaganda` names. `ReviewSubmission` now carries `run_id`/`verdict`/`expected_label` instead of `ai_output_id`/`is_correct`/`human_label`. Admin-token gating (`require_admin_token` dependency) is unchanged.
- **`api/routers/status.py`** (new) — `GET /snapshot-status` reads the latest `ops.pipeline_runs` row (the freshness contract now that `serving.refreshes` is gone); `GET /eval-accuracy` is the public human-agreement overlay via the review service. Neither route is admin-gated — both are public honesty surfaces.
- **`api/queries/docs.py`**, **`api/models/docs.py`**, **`api/routers/docs.py`** (new) — `GET /docs/{doc_id}`, the universal drill-down: document core fields + `admission_class` + `source_url`, subtype extras (news/reddit/x_post — all three keys always present, exactly one populated), every CURRENT analysis result (per task: `confidence`, `model_id`, `prompt_version`, and task-specific `fields` — sentiment/favorability for `text`, target mentions for `targets`, density+techniques for `propaganda`, claims list for `claims`, stylometrics for `bot`, an extracted-citation count for `citations`), and citations in/out — each side resolved with NO time bound, url-only outbound citations included. 404 on an unknown `doc_id`; otherwise resolves regardless of document age (owner decision 2026-07-24).
- **`api/models/ops.py`** (new) — `PipelineRunModel` shared by `status.py`'s `SnapshotStatusResponse` and `admin.py`'s `PipelineRunsResponse`.
- **`api/routers/admin.py`** rewritten: `POST /run/etl` and `POST /run/full-pipeline` now call `scheduler/pipeline.py::run_pipeline()` (the new-stack pipeline) instead of `etl/loader.py`/`job_runner.py`; the old `/cache-status` endpoint is replaced by `GET /pipeline-runs` (recent `ops.pipeline_runs` rows). Auth gating (`require_admin_token`, `enforce_trigger_cooldown`, per-route rate limits) is unchanged.
- **`api/routers/health.py`** rewritten: `SELECT 1` through a pooled Postgres connection (`common/db.py`) instead of `sqlite3.connect`. Catches `RuntimeError` (no `CIVIC_DATABASE_URL`) and `psycopg.Error` (unreachable server) and reports `status: "degraded"` rather than raising — the endpoint itself must never 500.
- **`api/server.py`** + **`api/routers/__init__.py`** rewired: all thirteen routers mounted (twelve under `/api/v1` — the seven panels from the parallel workstreams, `admin`, `docs`, `review`, `status`, `auth_bootstrap` — plus the unversioned `health`). `api/routers/data.py` and `api/cache_utils.py` deleted; no `SnapshotCache`/`cache_dir` reference remains anywhere under `analysis/src/api/`.
- **`.agent/rules/media-analysis.md`** — Phase 9 section appended: the fact/curated/derived lean invariant, lean never fed to an LLM prompt, `sampled`/`official_record` labeled distinctly, windows scope denominators never document existence, every aggregate carries `RangeMeta`.

## Why

- **`reporting/review.py` stays untouched, not deleted.** It is Phase 11's job to retire the SQLite stack; this workstream's contract was "do not import any `reporting/*`", not "delete `reporting/*`". `analysis/src/review/` is a parallel, independent module — the two never share code, so leaving the old one running is zero-risk.
- **`data.py`/`cache_utils.py` deleted, not left running.** Unlike `reporting/review.py`, these files have no independent life after this wave — every route they served (`/sentiment`, `/bot-activity`, `/narratives`, `/propaganda`, `/entity-posts`, `/outlet-profiles`, `/movers`, `/eval-accuracy`, `/snapshot-status`) is now served by a strictly-live panel router or this workstream's `status.py`. Leaving them mounted would mean two competing implementations of the same path.
- **Module-level functions for `review/service.py`, not a class.** Every other Phase 9 query module (`queries/narratives.py`, `queries/bots.py`, this workstream's own `queries/docs.py`) is a set of top-level functions over a shared Postgres pool, not a class instantiated with a `db_path`. The old `ReviewService(db_path)` shape was SQLite-era; matching the established Phase 9 convention won out over preserving the old class name.
- **`analysis.evals`/`analysis.golden_labels` upsert, not insert-only.** `analysis.evals.run_id` is `UNIQUE`, and the schema comment calls it "append-only-safe" in the sense that a *reprocess* can't invalidate a past eval (it points at a specific `run_id`) — it does not forbid a reviewer correcting their own submission for the same run, which the old SQLite `ai_output_evals` supported via `INSERT OR REPLACE`. `ON CONFLICT (run_id) DO UPDATE` preserves that reviewer-facing behavior against the new UNIQUE constraint.
- **`/docs/{doc_id}` has no window parameter at all**, not an optional one defaulting to unbounded — the owner decision was that a document's existence is never gated by time. Giving the endpoint a window param at all would invite a future caller to assume the omission means "recent," which is the opposite of the contract.

## Judgment calls

- **`account_tier` is a valid `ReviewTask`/queue-`task` value that always returns an empty queue.** `analysis.runs` for `account_tier` are author-scoped (`doc_id IS NULL`); the queue's `JOIN corpus.documents` can never match them. Rather than special-case the enum to exclude `account_tier`, the queue simply — and correctly — returns nothing for it; reviewing author-level outputs would need a different UI shape entirely, out of scope here.
- **`submit()`'s `ValueError`s map to 404 vs 400 by substring match** (`"not found"` in the message -> 404, else 400) in `routers/review.py`. This is the pragmatic minimum rather than distinct exception types, mirroring how `routers/narratives.py` maps every `resolve_time_range` `ValueError` to 400 uniformly.
- **`citations` task's drill-down "fields" is a bare `citation_count`.** Unlike `bot`/`text`/`targets`/`propaganda`/`claims`, `analysis.citations` isn't a per-run "result" row with its own confidence/label — it's the edge list `citations_in`/`citations_out` already surface in full. A citations-task run still appears in `analysis_results` (it is a real current run with its own `model_id`/`confidence`), just with a minimal field set.
- **`review/service.py` doesn't resolve entity names** in `target_mentions`/`favorability_stances` — raw `entity_id`s only, matching the "key result fields" framing rather than a full drill-down. Same for `docs.py`'s analysis-result fields. A future consumer needing display names can join `corpus.entities` itself.
- **`GET /snapshot-status` and `GET /eval-accuracy` are not admin-gated**, unlike every route in `review.py`/`admin.py` — both are the public freshness/accuracy honesty surfaces the UI reads on every page mount, carrying no per-row or reviewer-identity data.
