# 2026-07-24 — Phase 9 workstream B: narratives + propaganda panels (strictly live)

The narratives and propaganda panels now aggregate `corpus.*`/`analysis.*` live at request time, per the Phase 9 strictly-live architecture (`docs/audit-trail/analysis/2026-07-24-phase9-prewave.md`). No caching, no rollup table — every request runs fresh SQL against the current corpus. Both endpoints accept a preset `window` (`24h`/`7d`/`30d`/`90d`/`all`) XOR an explicit `from`/`to` range (owner decision 2026-07-24: presets are a convenience default, not a wall — historical data, including officials' `official_record` posts predating every preset, stays fully queryable).

## What shipped

- **`analysis/src/api/queries/narratives.py`** — `get_narratives(start, end, limit, window_label)`: ranks narratives by in-range member-doc count (`analysis.narrative_docs` joined to `corpus.documents`), then batch-fetches per-narrative source breakdown (news/reddit/x), a daily timeline, net sentiment (`analysis.sentiment_results` scaled -100..+100, floored by `get_settings().aggregation_min_confidence`), a propaganda-flagged fraction (member docs with `>=1` validated technique), a bot-pushed fraction (member docs whose author's `analysis.author_bot_scores.score >= BOT_SCORE_AUTHOR_EXCLUSION` — the one metric this threshold *measures* rather than excludes), the narrative's derived lean (`analysis.narrative_leans`, omitted entirely when no row exists), and up to `MAX_EVIDENCE_PER_SAMPLE` member-doc samples (ranked by `narrative_docs.confidence`). **Citation resolution never applies a time bound to the cited (target) doc** (owner decision 2026-07-24): a member doc inside the range may cite a doc — including an `official_record` doc — far outside it, and that edge still renders fully resolved (`doc_id`, `source_url`, `published_at`, `admission_class`) rather than being dropped or window-filtered. Only the citing (source) doc is scoped to `[start, end]`.
- **`analysis/src/api/queries/propaganda.py`** — `get_propaganda_overview(start, end, window_label)`: the denominator behind `total_eligible_docs`/`flagged_docs`/`mean_score` is `analysis.runs` (`is_current`, `status='done'`, `task='propaganda'`), **not** `propaganda_results` rows — a deterministic pre-filter-clean doc gets a real run row (mirrors `engine/citations.py`'s convention) and belongs in the denominator, diluting the rate, not just the flagged numerator. Bot-authored docs (`author_bot_scores.score >= BOT_SCORE_AUTHOR_EXCLUSION`) are excluded from every rate denominator here (unlike the narrative bot-pushed fraction, which measures them). Per-technique counts come from `analysis.propaganda_techniques` (all six enum values rendered, zero-count included) with a few verbatim evidence spans truncated to `SNIPPET_MAX_CHARS`. News-vs-social and by-party splits are computed from one shared eligible-doc query; by-party keys on `corpus.entities.lean` (there is no separate `party` column in the schema — `lean` is the only curated affiliation value) joined through `corpus.author_profiles.entity_id`, with entity-less authors and entities carrying `lean='unknown'` both bucketed under `'unknown'` rather than excluded.
- **`analysis/src/api/models/narratives.py`**, **`analysis/src/api/models/propaganda.py`** — CamelModel response shapes: `NarrativesResponse` (`range` + `narratives: List[NarrativeSummaryModel]`), `PropagandaOverviewModel`. Both embed a `RangeMeta` (from the updated `models/common.py`): resolved `start`/`end` (null = unbounded), `sampledDocCount`/`officialRecordDocCount`, and the distinct `modelIds` among contributing runs. For narratives, `modelIds` is drawn from `text`/`propaganda`-task runs on in-range member docs (the two tasks whose numbers are actually rendered per narrative); for propaganda it's the `model_id`s on the eligible-doc set itself. `cited_docs`/`member_doc_samples`/`examples` all use the shared `SampleDocModel`.
- **`analysis/src/api/routers/narratives.py`**, **`analysis/src/api/routers/propaganda.py`** — thin `APIRouter`s (not mounted — a later workstream registers them). Both take `window` XOR `from`/`to`, defaulting to `window='30d'` when neither is given; a `ValueError` from `resolve_time_range` (unknown window, or both modes given at once) maps to 400.
- **Tests**: `analysis/tests/test_api_queries_narratives.py`, `analysis/tests/test_api_queries_propaganda.py` (pure computation-helper tests + gated integration tests seeding scenarios through `pg_fixture`), `analysis/tests/contract/test_narratives_contract.py`, `analysis/tests/contract/test_propaganda_contract.py` (gated, mount the routers standalone via `TestClient`, snapshot the JSON shape). Notably: a citation from an in-range doc to an `official_record` doc six months outside the range still resolves fully in the narrative payload; deterministic pre-filter-clean propaganda runs count in the denominator, not just flagged docs; the by-party split buckets unknown/entity-less authors instead of excluding them; `RangeMeta.model_ids` reflects mixed seeded `model_id` values on both endpoints.

## Why

- **Strictly-live, no `serving` schema** (see the analysis-layer prewave entry) — `queries/base.py`/`constants.py`/`models/common.py` were pre-built scaffolding; this workstream and workstream A (sentiment + entities, see the sibling entry) are its first two consumers.
- **Historical data stays queryable, windows scope denominators only** (owner decision 2026-07-24, applied mid-task) — `resolve_time_range` was extended (by the foundation, not this workstream) to accept an unbounded `'all'` window or an explicit `from`/`to` range, because an officials' `official_record` backfill can be far older than any preset window and must remain reachable. This workstream is the first to combine that with a citation-graph overlay, which sharpened the rule further: a **window scopes which narratives rank and which docs count toward an aggregate — it must never gate whether a cited document resolves.** Dropping or window-filtering a cited doc would silently misrepresent the citation graph as smaller than it is.
- **Denominator = runs, not results** (propaganda) — `propaganda_results` only exists for docs that were actually density-scored; a doc whose deterministic pre-filter found no charged vocabulary still gets a `done` `analysis.runs` row (no LLM call spent) and is a real "not flagged" verdict. Counting only `propaganda_results` rows would inflate the flagged rate by excluding every clean doc from the denominator.

## Judgment calls

- **`queries/constants.py` is a locked foundation file** (per this task's scope), so panel-specific constants (`DEFAULT_NARRATIVE_LIMIT`, `SOURCE_TYPE_LABELS`, `PROPAGANDA_TECHNIQUES`, sample/evidence caps not already ported) live as module-level constants in `narratives.py`/`propaganda.py` themselves, matching the pre-redesign `reporting/aggregators/propaganda.py`'s own convention of file-local constants alongside the shared `aggregators/constants.py`.
- **`_time_filter()` is duplicated** (not shared) between `narratives.py` and `propaganda.py` — a ~12-line SQL-bound-clause builder. `queries/base.py` is off-limits for this task; promoting it there is a natural follow-up once a third consumer needs it (see Follow-ups).
- **By-party split key is `corpus.entities.lean`**, not a `party` column — the schema has no separate party column (`0001_north_star.sql`'s "ONE flat lean convention" comment); the task prompt's wording ("`entities.party`") doesn't match the schema and is corrected here.
- **Citation/member-doc sample confidence**: a citation's sample confidence comes from `analysis.runs.confidence` via `citations.run_id` (the citation-extractor run, deterministic confidence `1.0` by convention); a member-doc sample's confidence comes from `narrative_docs.confidence` (the claim-match confidence recorded at cluster-insert time) rather than any one task's run confidence, since a member doc need not have a sentiment/propaganda run at all. Rows lacking a resolvable confidence are filtered out of the *sample* list in SQL (never fabricated) but still counted in raw counts (`citation_count`, `total_eligible_docs`) where applicable.
- **By-party ordering** is alphabetical by party name — a simpler, non-judgment-laden choice than the pre-redesign aggregator's "worst offender first" (`flagged_rate_pct` desc) ordering.
