# 2026-07-24 — Phase 9 workstream C: bot detector, outlet profiles, movers (strictly live)

The Bot Detector panel, the Outlet Profiles panel, and the window-over-window Movers ticker now aggregate `corpus.*`/`analysis.*` live at request time, per the Phase 9 strictly-live architecture (`docs/audit-trail/analysis/2026-07-24-phase9-prewave.md`). No caching, no rollup table — every request runs fresh SQL against the current corpus.

## What shipped

- **`analysis/src/api/queries/bots.py`** — `get_bot_activity(start, end, window_label)`: automation rate (share of in-window, confidence-floored `analysis.bot_signals` docs whose author's `analysis.author_bot_scores.score >= BOT_SCORE_AUTHOR_EXCLUSION` — keyed off the AUTHOR's score, not that particular doc's own label), a behavioral-signal breakdown (mean stylometrics per `bot_label` bucket), account-age buckets for distinct bot-flagged authors (`corpus.authors.account_created_at`), per-entity bot rates (via `corpus.author_profiles.entity_id` — unlinked general-public authors are not rolled up, they surface only as flagged examples), bot-pushed narratives (`analysis.narrative_docs` member docs ranked by bot-authored fraction, suppressed below `MIN_TARGET_SAMPLE_N` in-range member docs), and flagged example accounts/docs. A flagged account's lean surfaces only as a derived `LeanLabel` from `analysis.author_leans`, omitted entirely when no row exists or the row's lean is `'unknown'`.
- **`analysis/src/api/queries/outlets.py`** — `get_outlet_profiles(start, end, window_label)`: per-domain/subreddit net tone x bot rate, volume, and confidence-ranked samples. Preserved exception: bot-authored content is INCLUDED here (no `BOT_SCORE_AUTHOR_EXCLUSION` filter at all) — the bot rate IS the signal being measured; the response carries a `disclaimer` field stating this.
- **`analysis/src/api/queries/movers.py`** — `get_movers(current_start, current_end, previous_start, previous_end, current_window_label)`: window-over-window tone movers (entity resolved via `author_profiles`/`news_articles.outlet_entity_id`/`reddit_posts.subreddit_entity_id`) and the single top favorability mover (`analysis.favorability_stances`, entity_id direct FK), both bot-excluded and floor-suppressed (`MIN_TARGET_SAMPLE_N` in both compared periods). Two adjacent periods share a boundary instant (`previous_end == current_start`); `movers.py`'s own `_time_filter` deliberately uses an EXCLUSIVE upper bound (unlike the sibling panels' inclusive convention) so a doc timestamped exactly at that instant lands in exactly one period.
- **`analysis/src/api/models/bots.py`**, **`models/outlets.py`**, **`models/movers.py`** — CamelModel response shapes: `BotActivityResponse`, `OutletProfilesResponse`, `MoversResponse`. `BotActivityResponse`/`OutletProfilesResponse` each embed one `RangeMeta` (resolved bounds, sampled/official_record split, distinct `modelIds`); `MoversResponse` embeds two — `currentRange`/`previousRange` — one per compared period.
- **`analysis/src/api/routers/bots.py`**, **`routers/outlets.py`**, **`routers/movers.py`** — thin `APIRouter`s (not mounted; a later workstream registers them under `/api/v1`). `GET /bot-activity` and `GET /outlet-profiles` take `window` (preset or `'all'`, default `'30d'`) XOR explicit `from`/`to` — historical data stays queryable forever (owner decision, mid-task correction). `GET /movers` takes the same shape but rejects `window='all'` with 400 (an unbounded range has no preceding equal-length period to compare against); for an explicit `from`/`to`, the router computes the previous period as the same duration immediately preceding `from`. All three map a query-layer `ValueError` to 400.
- **Tests**: `analysis/tests/test_api_queries_bots.py`, `test_api_queries_outlets.py`, `test_api_queries_movers.py` (pure `_time_filter`/`_age_bucket_label` tests + gated integration tests seeding scenario rows through `pg_fixture`), `analysis/tests/contract/test_bots_contract.py`, `test_outlets_contract.py`, `test_movers_contract.py` (gated, mount each router standalone via `TestClient`, snapshot the JSON shape).

## Why

- **Strictly-live, no `serving` schema** — these are three more consumers of the Phase 9 prewave scaffolding (`queries/base.py`/`constants.py`, `models/common.py`).
- **Historical data stays queryable forever, EVERY panel** (owner decision, mid-task correction 2026-07-24): windows scope aggregate denominators, never document existence. `resolve_time_range` makes `'all'` and an explicit `date_from`/`date_to` first-class on bot-activity/outlet-profiles. Movers is the deliberate exception — a window-over-window comparison is meaningless without a bounded "previous period" to diff against, so `'all'` is rejected there specifically, not silently reinterpreted.
- **RangeMeta is the disclosure mechanism for that freedom**: a caller who asks for a multi-year range on bot-activity might span a bot-detector model swap or an `admission_class` regime change (0003 shipped 2026-07-23). Surfacing `modelIds` and the two admission-basis counts lets the UI label that instead of presenting one falsely-continuous series. Movers carries two `RangeMeta`s because the comparison itself has two distinct provenances.
- **Automation rate keys off the author, not the doc's own label**: "bot-scored authors' share of in-window analyzed docs" is a statement about accounts, not about any single post's classification — an author whose aggregate score crossed the exclusion threshold counts fully even on a post the model itself called human, because the metric being reported is account-level automation prevalence, not per-post accuracy.
- **The outlet-profiles bot-inclusion exception is load-bearing, not an oversight**: every other panel treats a bot-scored author's content as noise to exclude from discourse denominators; outlet-profiles is the one surface built to show HOW MUCH of an outlet's/subreddit's activity looks automated, so excluding it would erase the exact thing the panel exists to measure.

## Judgment calls

- **Per-entity bot rate has no "unlinked" catch-all bucket.** Unlike the pre-redesign `entity_registry`'s YAML catch-alls (`other-x-users`, `other-subreddits`), the new schema has no first-class "general public" entity row — `corpus.author_profiles.entity_id` is simply NULL for unlinked authors. Rather than inventing a synthetic catch-all entity, unlinked authors are omitted from `byEntity` and surface only via `flaggedAccounts`/`flaggedDocs`. Scope reduction, not an oversight.
- **Flagged-account eligibility reuses `MIN_SAMPLED_AUTHOR_POSTS`/`MIN_SAMPLED_AUTHOR_FOLLOWERS`/`MAX_SAMPLED_AUTHOR_CARDS`** (ported from the pre-redesign `sentiment/entities.py` footprint floor) rather than inventing a bot-panel-specific threshold — the underlying judgment ("don't give a one-post, no-follower account its own card") is identical.
- **`_time_filter`'s inclusive-vs-exclusive upper bound is a deliberate per-module divergence.** `bots.py`/`outlets.py` match the sibling `narratives.py` convention (`<=`, a single range has no adjacency concern). `movers.py` uses `<` specifically because it compares two periods that share a boundary instant.
- **Movers entity resolution has no separately-seeded outlet/subreddit test coverage** — the tone-mover query's `COALESCE(author_profiles.entity_id, news_articles.outlet_entity_id, reddit_posts.subreddit_entity_id)` is exercised via the `author_profiles` arm only; the other two arms share the same join shape and are lower incremental risk than the effort to seed `raw.articles`/`raw.reddit_posts` FK chains. Flagged as a coverage gap, not asserted as safe.
- **Bot-pushed narrative ranking and per-entity bot rate both look up `analysis.author_bot_scores` over the UNION of `bot_signals`-scanned authors and `narrative_docs`-member authors** — a narrative-member doc need not itself have a `bot_signals` row to know whether its author is bot-scored. An earlier draft scoped the score lookup to `bot_signals` authors only and silently produced a 0% bot-pushed fraction for every narrative; caught by `test_bot_pushed_narrative_reported_at_or_above_sample_floor` before it shipped.
