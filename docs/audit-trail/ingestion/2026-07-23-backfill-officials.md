# 2026-07-23 — Officials backfill: `civic-ingest backfill-officials`

`civic-ingest backfill-officials` is a new, re-runnable subcommand that tops up `raw.x_posts` for every tracked active official up to a provenance-scoped minimum stored-post count, so an official who was only ever captured through the topic-search or per-pass officials pull isn't stuck with a thin history. This is Postgres redesign Phase 8 prep (owner-approved 2026-07-23; plan `docs/todos/pg-redesign.md`), landed alongside the analysis-side `admission_class` work — see `docs/audit-trail/analysis/2026-07-23-admission-class.md` for the Python/SQL half this command's output feeds.

## What shipped

- **`ingest/internal/runner/backfill_officials.go`**: `loadActiveOfficials` reads `corpus.entities WHERE kind='official' AND active=true`, returning each row's `entity_key` (the bare lowercase X handle) and `editorial` BOOLEAN. `targetFor` maps `editorial=true` to `editorialBackfillTarget=100` (the 16 hand-curated verified officials — the highest-signal surface Civic Lens tracks) and `editorial=false` to `promotedBackfillTarget=25` (the ~535 accounts promoted wholesale from `known_political_x_accounts.yaml`). `postsNeeded(target, stored)` floors the shortfall at zero. `countStoredPosts` counts `raw.x_posts` rows by `author_id` regardless of `is_official_tier` — this count *is* the resumability checkpoint: no separate progress table, a re-run after a crash or a cap-stop just recomputes the shortfall and picks up where it left off.
- **`runBackfillOfficials`** walks every active official in `entity_key` order: resolves the X user ID (cached via the existing `resolveOfficialUserID`/`raw.x_users` path), checks the shortfall, and — if nonzero — pulls up to `need` posts in a single `UserTimeline` call (the API's `max_results` ceiling of 100 already covers both targets in one page from a cold start, so no pagination is needed). Spend is tracked two ways: against the required `--spend-cap-usd` single-use ceiling for *this invocation only* (in-memory, not persisted), and through the existing `XBudgetTracker` so the persistent monthly `ops.x_api_budget` ledger reflects backfill spend too. A per-official failure (suspended/renamed handle) is logged and counted, never aborts the remaining walk; the command exits nonzero exactly when at least one official errored.
- **`civic-ingest backfill-officials --spend-cap-usd <N>`** (`cmd/civic-ingest/main.go`): the flag is required (`MarkFlagRequired`) and validated `>0` before any work starts. The command requires a Postgres `--db` — `corpus.entities` has no SQLite counterpart — and fails fast with a named error otherwise.
- **Test coverage**: `backfill_officials_test.go` (pure shortfall math, editorial-vs-promoted target selection, resume-skip when already at target, shortfall-fetch, cap-stop-cleanly, per-official-error-does-not-abort-walk) all run against a stub X API, no DB. `backfill_officials_integration_test.go` (`TestPostgresLoadActiveOfficials`, `TestPostgresCountStoredPosts_ResumeState`) is gated on `CIVIC_TEST_POSTGRES_DSN`, exercised this task against a throwaway `postgres:17-alpine` container.

## Design notes (owner-facing)

- **`corpus.entity_aliases` handles are deliberately not walked.** An official's alternate handles (e.g. `@POTUS`'s `@realDonaldTrump`/`@WhiteHouse` aliases, 30 rows total across the registry) are not backfilled — the target is defined per `corpus.entities` row (one official, one primary handle), not per handle, matching the scope of the brief that authorized this command. If per-alias backfill is wanted later, it needs its own design pass (aliases don't carry an independent `editorial` flag today).
- **Single-page fetch.** `UserTimeline` is called once per official per invocation, sized to exactly the shortfall. An official whose returned page mostly overlaps posts already stored (upsert no-ops on `ON CONFLICT`) may still fall short after one run — the resumability contract means a later invocation (same command, no flags to resume) picks up the remainder, identical to a cap-stop or a crash-and-restart.
- **`--spend-cap-usd` is single-use, not cumulative.** It bounds only the current invocation; it is independent of (and additive to) the persistent monthly `ops.x_api_budget` ceiling, which every call's cost is still recorded against regardless.

## Why

- Officials with a thin `raw.x_posts` history (never hit by the topic-search pass, only lightly touched by the per-pass officials pull) can vanish from account-level dashboards for lack of stored data even while they remain politically active — this command is a one-time (re-runnable) remediation, not a new recurring pass.
- Editorial vs. promoted provenance already exists as a curated signal (`corpus.entities.editorial`, seeded in `0002_entity_registry_seed.sql`); reusing it to size the backfill target avoids over-fetching the 535 promoted accounts to the same depth as the 16 editorially verified ones.

## Validation performed this task

- Fresh throwaway `postgres:17-alpine`: `civic-ingest migrate` applies `0001`→`0003` cleanly; a second `migrate` run is a clean no-op (idempotent).
- `cd ingest && go test ./... -count=1` — all packages pass, including the new `backfill_officials_test.go` cases.
- `CIVIC_TEST_POSTGRES_DSN` gated integration tests (`TestPostgresLoadActiveOfficials`, `TestPostgresCountStoredPosts_ResumeState`, plus the pre-existing Postgres suite) — all pass against the real container.
- CLI guard checks against the real binary: missing `--spend-cap-usd` rejected (`required flag(s) "spend-cap-usd" not set`); `--spend-cap-usd 0` and a negative value both rejected (`must be greater than 0`); pointing `--db` at a SQLite file rejected (`backfill-officials requires a Postgres --db: corpus.entities does not exist on the SQLite backend`).
- Cross-cutting fix (this integration wave, not a workstream deliverable): `ingest/internal/config/config.go`'s strict YAML decoding (`KnownFields(true)`) was rejecting the real `data/seeds.yaml`'s Python-only `domain_filter` section on every Go CLI command (pre-existing breakage from the Phase 4 filter work, reproducible on the `x` command before this fix too). Fixed by adding a `DomainFilter map[string]any` field to `config.Config` (Python-ETL-only, Go never reads it) so strict decoding parses and ignores the section. Verified by running `civic-ingest crawl --duration 1s` against the real `data/seeds.yaml` and a throwaway Postgres DSN: `config.Load` now succeeds (previously failed with `field domain_filter not found in type config.Config`).
