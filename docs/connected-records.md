# Connected Records

Connected Records is the active Civic Lens initiative after the R-68 public redesign. It holds the product direction, four-plane architecture, phases (0 to 4), first pilot assignment, and experiments. The repository work queue, accepted backlog, and pending decisions live in the [roadmap](roadmap.md). Start at the [architecture lookup table](architecture.md#lookup-table).

## Direction

Civic Lens lets a citizen follow a public claim through an official decision to a measured outcome. Start with a question that matters to the reader. Give each answer a date, an accountable actor, and a one-step path to the original evidence.

One [relationship pipeline](connected-records/pipeline.md) connects records across many dimensions of the data, implemented across four explicit data planes. It aggregates connections by official, issue, bill family, committee, and time, and shows them in an informative, interactive way. The aim is to make inaccessible or hard-to-connect public records visible to a regular reader. The site shows what the records say and how they connect. It never states a conclusion. The reader draws the conclusion. The same rules apply to every official, issue, and dimension, so no single case or topic shapes the output. Single cases, such as the VA claims backlog, test the pipeline. They are not the product.

The audience is regular citizens who want transparency in U.S. national politics. State and local coverage are possible future extensions. Readers start with reviewed accounts and can inspect the supporting evidence in one step. The editorial flow and Mosaic v2 identity are agreed.

Data is the product. The product is only as good as its data, so data and database schemas are a first-class feature. Design them as deliberately as any public page. The goal is typed, version-bound links between people, records, bills, provisions, votes, sponsorships, executive actions, document changes, issues, and outcomes.

Design for scale under a solo maintainer. Automate every step that does not need human judgment. Code approves official fact records and deterministic structural paths. The product scales on deterministic facts and rule-gated aggregates, while human-reviewed judgment links stay bounded to sustainable solo-maintainer review capacity. A model prediction is never an approval.

Teaching the reader is a first-class goal. Each page answers more questions than it opens (owner, 2026-11-06) and explains what each record is and why it matters in plain words. Where a bill, vote, action, or term is ambiguous or technical, the page gives an AI summary in plain words with its AI label. Code checks each summary against its source, targeting grade 12 and rejecting above 14. Use three-layer progressive disclosure so regular readers see plain clarity and one guardrail line first, interactive exploration second, and full audit metadata on demand.

Derived insights make Civic Lens more than a connector to source APIs. Code computes each metric and publishes a method note, denominator, base rate, and coverage limit. A person reviews any judgment before publication. [Candidate features](connected-records/features.md) lists the insights and features to investigate. Investigation can remove any of them.

## Current stage

Civic Lens is deployed and past its MVP, first deployment, and R-68 public redesign. `PublicApi` serves every public page from restricted `public_api` views, and the publisher writes data only. Current capabilities and ownership are in [architecture](architecture.md). Deployment, backups, recovery, and live checks are in [operations](operations.md).

Work now moves into Connected Records through reviewed, tested iterations. Plane 1 deterministic facts and Plane 3 statistical aggregates scale in parallel with the zero-cost setup checks and Phase 1 private pilot on frozen data. The [roadmap](roadmap.md) holds the full work queue and settled decisions D-18 through D-24. Move accepted behavior into its feature reference as each phase ships.

## First assignment

First run the [setup experiments](connected-records/pipeline.md#before-the-pilot-opens-its-holdout) in priority order, starting with speaker controls, frozen release export and input bundle, the `RelationshipRevision` binding dry run, and the full-corpus distractor retrieval check. Then start a fresh branch from `origin/main`. Read the [pipeline rules](connected-records/pipeline.md), [claims workflow](connected-records/claims.md#proposed-workflow-and-ownership), [relationship review](architecture/statements.md#relationship-drafting), [evaluation plan](connected-records/evaluation.md), and [trial results](connected-records/experiments/evidence-trials/results.md). Use the frozen published release export and pinned external bundle in development.

Build one private review flow extending the existing relationship-drafting and review handlers under settled decisions [D-19 and D-20](roadmap.md#pending-decisions). Put the attributed quotation, speaker origin, and date beside the exact bill edition and passage span, the roll-call question and motion polarity, and the member's recorded cast when one exists. Let the maintainer accept, reject, or record `InsufficientEvidence` (with conditional reopen on evidence fingerprint change). Bind the decision to the evidence revisions, candidate-set digest, retrieval method version, and `as_of_utc` cutoff so any replay reproduces it. Keep public contracts unchanged until the pilot passes.

Demonstrate the flow on a supported direct-motion link, a package or procedural vote link, a wrong-speaker control, and a tempting wrong link. Then test on the pre-registered seeded holdout of unseen bill families sized under the [pipeline evaluation](connected-records/pipeline.md#evaluation), using blinded intra-rater re-labeling and an LLM devil's-advocate rubric check (never an approval) in place of a second human annotator. Capture candidate coverage in the first five slots, unsupported attribution rate and risk, wrong-speaker count, abstention rate, and review minutes per accepted link. Keep cases without a sufficient vote and retrieval failures in the denominator. All nine prior trial families are development data and stay out of the holdout.

Hand back the private workflow in its PR with a `--bundle` replay command, pinned inputs, baseline and candidate counts, intra-rater kappa, and decisions a replay can reconstruct. List unresolved cases and the missing evidence for each. The pilot can finish with an inconclusive result. Use the [evaluation criteria](connected-records/evaluation.md#pilot-decision-and-feedback) to decide whether to retain the lexical baseline, refine a specific stage, or scope a public trial. Before any public Evidence Path ships, build the three-state reader prototype and run the 6-person think-aloud test in [reader decisions](connected-records/reader.md#decision-test).

## Which research would change the next build?

The [five completed trials](connected-records/experiments/evidence-trials/results.md) establish the starting point. Only the first row and the setup checks belong to the private pilot. Reopen the other questions when the named trigger occurs and the result would change a product decision.

| Question | What the completed trial established | Next decision and evidence needed |
|---|---|---|
| Can a maintainer connect a quote to the right decision at real corpus scale? | Explicit links recovered 4 of 4 selected pairs on 6 bills and 5 roll calls, but two pairs treated a whole-bill passage vote as provision evidence. Every method returned candidates on 3 of 3 insufficient cases because none could abstain. | Run speaker controls and full-corpus distractor retrieval first. Then compare role-aware methods against BM25 plus explicit bill-vote join and a calibrated abstention threshold on unseen families. Score coverage, attribution rate, attribution risk, wrong speaker, and review minutes separately. |
| Did a provision survive into the next edition? | Text matching got 8 of 8 continued provisions right and 1 of 2 dropped provisions right. The one false continuation changed legal effect. | Trigger: a change timeline is scheduled. Test at least 29 dropped or changed-mechanism transitions from unseen families. Keep uncertain transitions in human review. |
| Did a funded project reach delivery? | The Deerfield case linked an obligation and a reported opening, though the opening report omitted the FAIN. | Trigger: a delivery stage is scoped. Test 5 recipients including similar-name decoys. Until then, show each verified stage and its source. |
| Do shared sponsors form a recurring group? | Removing the most widely backed early bill cut later overlap from 22 of 58 repeated pairs to 1 of 15 (consistent with the degree null). | Do not run now. Revisit only with full-session windows, leave-one-out range across all bills, and a party/committee-preserving null. |
| Do readers understand linked evidence and avoid false inferences? | The two-order instrument ran with zero participants and tested neither quote-to-vote links nor insufficient evidence. | Build the three-state Evidence Path mockup and run a 6-person think-aloud before any Phase 3 UI build. Test navigation separately against the shipped DR6 header. [Reader trial](connected-records/reader.md#decision-test). |

## Decisions to take in order

1. **Lock solo-maintainer pipeline foundations (settled as [D-18 to D-24](roadmap.md#pending-decisions)).** Run the zero-cost setup experiments first, especially speaker controls on multi-speaker releases, frozen release export and bundle, `RelationshipRevision` binding dry run, and full-corpus distractor retrieval. Start the private pilot on frozen data with no public contract change. Keep the current `release_issues` table without a versioning migration; fix missing legacy definitions in `PublicationCatalog`.
2. **Scale Plane 1 deterministic facts and Plane 3 aggregates in parallel with Plane 2 pilot work.** Prioritize code-approved structural features that need zero per-record human review: motion polarity and procedural effect on votes, edition-bound sponsorships with shell-bill detection, voice/UC "how it passed" (R-69), bill fate vs. base rate (R-69), and the source coverage meter (R-56).
3. **Keep PostgreSQL `public_api` views with `LATERAL` reads as the graph layer.** Only if a named query exceeds latency budgets with valid `LATERAL` SQL, add revision-ranged projection rows to `CivicLens.PublicApi`'s search database via `ReleaseIngest`. Do not add Apache AGE or Neo4j without a measured bottleneck. [Graph research](connected-records/graph.md).
4. **Build the three-state Evidence Path mockup and run the 6-person think-aloud before Phase 3 UI work.** Use three-layer progressive disclosure so regular citizens see plain clarity and one guardrail line first and audit metadata in a collapsed drawer. Test any new left rail against the shipped DR6 header as control. [Reader decisions](connected-records/reader.md#decision-test).
5. **Ship the first interactive Evidence Path route inside `PublicApi` and `PublicWeb` (Phase 4).** Use Razor SSR with server-rendered navigation and progressive JSON-backed panels. Add a release-independent withdrawal tombstone ledger so rollbacks cannot resurrect withdrawn records. Reopen a separate frontend shell only if a measured reader need fails on the current stack. [Delivery trial](connected-records/delivery.md#acceptance-trial).
