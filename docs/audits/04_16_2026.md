# Civic Lens Code Audit Report

This report audits the Analysis, Data, and UI layers against the project's invariants (traceability, confidence reporting, no fabrication) and its stated goal of measuring how political narratives propagate. The review covered reasoning-pipeline hardening, UI clarity for a non-expert user, schema fitness, and redundancy/dead-code. Findings have been remediated in walkthroughs [029](../walkthroughs/029-clustering-cut-llm-hardening.md) and [030](../walkthroughs/030-audit-layer-2-4-remediation.md); remaining open items are called out per section.

## 1. Reasoning Pipeline (LLM) — Analysis Layer

### Findings & Discrepancies
*   **Evidence spans unvalidated (invariant B2 violation):** `engine/analyzer.py:212–230` stored whatever the LLM returned in `sentiment_evidence_spans` and `entity_stances[].evidence_spans`. The prompt demanded verbatim phrases of 4+ words, but nothing verified the returned spans existed in the source text. Fabricated or paraphrased evidence was indistinguishable from real evidence and propagated into the UI and audit trail. **REMEDIATED** — a post-parse validator now drops any span under 4 words or not a case-insensitive substring of the source; confidence is capped at 0.3 when the model returned evidence but none verified.
*   **Confidence is LLM-self-reported with no calibration:** `float(response.get("sentiment_confidence", 0.5))` and the heuristic formulas (`0.5 + 0.5*(pos/total) - penalty`) are unmeasured. There is no golden test set, no accuracy-vs-confidence curve, no Platt scaling. Aggregator filters like `confidence >= 0.7` are therefore arbitrary. **OPEN** — prerequisite for any >95% accuracy claim.
*   **Post-LLM schema validation was missing:** `llm/base.py:91–103` passed the parsed JSON back to callers without checking that required fields existed or that numeric values were in-range. Missing fields silently defaulted via `.get(field, default)`. **REMEDIATED** — `parse_json_response` now takes the optional response schema and enforces required fields, types, enums, and numeric ranges; a violation raises `SchemaValidationError`, which triggers the existing heuristic fallback.
*   **No regression / golden-set harness:** existing Python tests in `analysis/tests/` verify that the pipeline *runs*, not that it is *correct*. A prompt change or a model swap has no way to surface an accuracy drop. **OPEN.**
*   **Prompt text was not recoverable per inference:** only the `prompt_version` string was stored in `ai_outputs`. Rebuilding `prompts.py` from git gets you the current version, not the prompt that produced a row three months ago. **REMEDIATED** — `save_ai_output` now accepts an optional `system_prompt` argument and embeds it under `output_json._system_prompt` for every row.
*   **Prompt quality gaps:** `TEXT_ANALYSIS_SYSTEM_PROMPT` has no worked examples, no chain-of-thought scaffold, and no explicit guardrail like "if you cannot find verbatim evidence, set confidence < 0.3". `BOT_SYSTEM_PROMPT` does not weight signals (a single spam-keyword match is treated the same as a 0.9 repetition score). **OPEN.**
*   **Schema looseness:** `TEXT_ANALYSIS_SCHEMA` allowed empty `sentiment_evidence_spans`, missing `minItems` on `entity_stances`, free-form `sentiment_reasoning`, and did not set `additionalProperties: false`. Evidence validation (above) now mitigates the first case, but the schema itself is still permissive. **OPEN.**

### Recommendations
*   Build a hand-labeled golden set (100–500 docs across news, Reddit, and X, with sentiment/favorability/bot labels and >0.8 Cohen's kappa between raters). Run it after every prompt or model change; fail on >2% accuracy drop.
*   Calibrate model-reported confidence against empirical accuracy on the golden set (Platt scaling or histogram binning). Replace the heuristic confidence formulas with calibrated output.
*   Tighten the JSON schemas (`minItems`, `additionalProperties: false`, `minLength` on reasoning fields).
*   Expand the prompts with worked examples, a self-verification step, and an explicit fabrication guardrail.

## 2. Analysis & ETL — Supporting Code

### Findings & Discrepancies
*   **Clustering was orphaned:** `engine/clustering.py` (101 LoC), `reporting/aggregators/story.py`, the `clusters` and `cluster_assignments` tables, and `ui/src/pages/StoryClusters.tsx` (358 LoC) were all active on the backend but the UI tab was commented out in `App.tsx:7`. Every pipeline run wrote cluster data that no user could see. **REMEDIATED** (walkthrough 029) — clustering removed end-to-end (~600 LoC).
*   **Legacy `Aggregator` wrapper class:** `reporting/aggregators/__init__.py` shipped a delegating `Aggregator` class with `TODO: Remove once all callers are updated`. Callers never were. **REMEDIATED** — callers (`server.py`, `job_runner.py`, `test_rich_aggregators.py`) now use domain aggregators directly; wrapper deleted.
*   **Dead settings:** `model_sentiment` in `common/settings.py:21` was defined but never read anywhere in the codebase. `clustering_threshold` existed only for the clustering pipeline. **REMEDIATED.**
*   **Over-engineered polling scraper:** `etl/polling.py` (~216 LoC with retries and error handling) powers a single card on the sentiment page. **OPEN** — leave for now, but worth consolidating if new features do not add consumers.
*   **Redundant GOP entity / proximity computation in `analyzer.py`:** `_extract_gop_entities` + `_find_entity_positions` run on every inference against a static GOP list. Could be memoized or precomputed, though cost is small. **OPEN** (deferred — the audit itself noted cost is small).
*   **Geo aggregator silently returned zeros:** `reporting/aggregators/geo.py` read `sentiment["sentiment_score"]` and `sentiment["gop_favorability"]`, fields the sentiment task never produces. Every country's `avg_sentiment` was 0.0 and every `avg_favorability` was 0.0 — the global heatmap showed a uniform yellow regardless of data. **REMEDIATED** (walkthrough 030) — label mapped to signed score × confidence; `avg_favorability` dropped from the response since the UI no longer displays it either.

### Recommendations
*   Treat the orphaned-feature pattern as a warning sign — if a surface is hidden in the UI, schedule the backend for removal rather than leaving it running "just in case."
*   When cutting a feature, delete the DB-writing path as part of the same change so `ai_outputs`-style tables do not accumulate silent dead weight.

## 3. Data Layer — Schema Fitness & Redundancy

### Findings & Discrepancies
*   **Schema cannot express narrative propagation (the project's stated goal):** the current tables — `docs`, `ai_outputs`, and ingestion frontier tables — support aggregate trend analysis but not causal propagation (origin doc, first-seen-at, cross-source citations). **SCHEMA REMEDIATED** (walkthrough 030) — `narratives`, `narrative_docs`, and `narrative_citations` tables landed in migration 007. **Writers still open** — narrative-extraction pipeline is a separate workstream.
*   **Three dead tables in the Go migrations:** `author_profiles`, `engagement_metrics`, and `reddit_comments_raw` had no writers. The orphaned `clusters` / `cluster_assignments` tables joined them after walkthrough 029. **REMEDIATED** (walkthrough 030) — migration 005 drops all five.
*   **Denormalized X metadata in JSON blobs:** `docs.metadata_json` buried `place_country_code`; the geo aggregator parsed it on every query. **REMEDIATED** (walkthrough 030) — migration 006 promotes `place_country_code` to a first-class column and adds `idx_docs_country`; backfilled from metadata_json. Other metadata fields (`author_id`, `followers_count`, `user_verified`) stay in the JSON blob because they're read only at bot-detection time, not on the aggregation hot path.
*   **No evaluation / auditability tables:** `ai_outputs` stored one confidence scalar per row with no place for human overrides, golden-set markers, or full prompt text. Walkthrough 029 embedded the system prompt in `output_json`, which was a stopgap. **SCHEMA REMEDIATED** (walkthrough 030) — migration 007 adds `prompt_versions` (writer wired in `save_ai_output`) and `ai_output_evals` (schema only; writer will land when the review workflow does).
*   **Cache as contract but no invalidation:** `data/cache/*.json` had no staleness awareness. **REMEDIATED** (walkthrough 030) — `_get_cached_or_fallback` now reads cache metadata and logs a warning when a snapshot is older than 24 hours, surfacing pipeline lag without blocking UI requests on live recomputation.

### Recommendations
*   Add narrative-propagation tables (`narratives`, `narrative_docs`, cross-source citation edges) before attempting to report anything about "spread."
*   Add `ai_output_evals` (human override + golden-set marker) and `prompt_versions` (full system prompt text by version) so calibration and audit become possible.
*   Drop the three dead tables in a Go migration.
*   Promote frequently-read metadata JSON keys to real columns on `docs`.

## 4. UI Layer (React)

### Findings & Discrepancies
*   **Broken page silently failing:** `ui/src/pages/GOPFavorability.tsx` called `/api/favorability`, an endpoint the server never defined. The page was not routed from `App.tsx` either. **REMEDIATED** — page and related API function (`fetchFavorability`) deleted; GOP favorability remains available as a card inside `PublicSentiment`, sourced from `/api/sentiment`.
*   **Global heatmap showed GOP favorability for non-US countries:** the tooltip at `GlobalHeatmap.tsx:247–248` surfaced an American-politics metric for every country on the map. To a Brazilian or German viewer, this looks like corrupted data. **REMEDIATED** — tooltip row removed; `avg_favorability` also removed from the `CountryStats` shape.
*   **Bot profiler exposed raw ML artifacts:** the 7×24 posting-cadence heatmap used raw day/hour indices with no timezone or threshold. The text-similarity distribution showed ">80% similar" with no baseline. **REMEDIATED** (walkthrough 030) — added explanatory captions above both panels: UTC time zone and human baseline on the heatmap; 20–30% natural-discourse baseline on the similarity distribution.
*   **"Social Media vs News" needed an explicit sample disclosure:** the original audit note claimed the social side was "sampled Reddit only" — that was a misread of the aggregator. `SOCIAL_PLATFORMS = {reddit_post, reddit_comment, social, x_post}` in `aggregators/constants.py`, so X posts are included and X is one of the most important sources for this project. **REMEDIATED** (walkthrough 030, corrected after review) — card title is "Sampled Social Media vs News Outlets", badge reads "Sampled Social (Reddit + X)", subtitle and footnote reference "Reddit + X", and the method-popover explicitly enumerates what is and is not in the sample.
*   **Page title implied universal sentiment:** `PublicSentiment` read as a nation-wide statement. **REMEDIATED** (walkthrough 030) — amber sampling-disclaimer banner added at the top of the page clarifying the data is sampled, time-windowed, and not a scientific poll.
*   **Dead UI exports:** `fetchBotProfiles` was defined and never called; `StackedBar` was exported only for the deleted `StoryClusters`. **REMEDIATED.**

### Recommendations
*   Every page that displays an ML-derived signal should include a one-line "how to read this" note with concrete thresholds, not just a legend.
*   Treat Reddit and X as labeled samples throughout the UI; avoid framing that generalizes to "social media" or "Americans."
*   When an endpoint is removed, remove the client function in the same change set to prevent silent 404s.

---
**Summary:** Walkthrough 029 closed the LLM-pipeline structural gaps (evidence validation, schema validation, prompt archival) and cut ~600 LoC of orphaned clustering code. Walkthrough 030 closed the layer-2/3/4 open items: UI sampling disclaimers across `PublicSentiment` and `BotActivityProfiler`, migrations 005/006/007 (drop dead tables, promote `place_country_code`, add `prompt_versions`/`ai_output_evals`/`narratives`/`narrative_docs`/`narrative_citations`), a real bug fix in the geo aggregator that had been returning uniform zeros, and cache staleness warnings. **What remains open** is the layer-1 work: a golden test set, a regression harness, and calibration. Those are prerequisite to any >95% accuracy claim. On the schema side, the narrative-propagation and `ai_output_evals` tables now exist but have no automated writers — the extraction pipeline and human-review workflow are each a separate design.
