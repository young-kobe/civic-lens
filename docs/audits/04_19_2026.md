# Civic Lens Code Audit Report — 2026-04-19

Full four-layer audit (Ingestion / Analysis / API / UI) focused on code quality, redundancy, dead code, inefficient processes, and refactor potential. Complements the 04-16-2026 audit, which focused on reasoning-pipeline correctness and schema fitness; this one is broader and more about hygiene and LOC.

## Scope & Method

- Four parallel deep-dive passes, one per layer. Findings are cross-verified against file:line where cited. A small number of bulk claims from the agent reports were spot-checked and corrected (noted inline where dropped).
- The codebase has evolved quickly — walkthroughs 032 (narrative pipeline), 033 (narrative reader + embeddings), 034 (review UI), 035 (goal narrowing), and 036 (account tier classification) all landed between the prior audit and this one. Narrative / claim / citation / account-tier code is included in scope but was not hand-audited as deeply as the older modules; flagged findings in those areas are conservative and may under-count.
- Walkthrough IDs and `OPEN` / `REMEDIATED` tags only refer to state at time of writing.

## 1. Ingestion Layer — Go (`ingest/`)

### Findings

- **Dead structs in `internal/ingest/model.go`.**
  - `ArticleRaw` (`model.go:31-39`) is defined but never instantiated; metadata is constructed ad-hoc at `runner/article_writer.go:68-76`. **REMEDIATED (walkthrough 044).**
  - `RedditComment` (`model.go:56-66`) is parsed by `extract/reddit/reddit.go:114-140` but never written to the DB or consumed downstream. **REMEDIATED (walkthrough 044).**
  - `CrawlResult` in `model.go:68-75` duplicates the same-named struct in `runner/crawl.go:24-29`; the `model.go` version has no importer. **REMEDIATED (walkthrough 044).**
- **Dead config field.** `internal/ingest/config.go:28` exposes `MaxConcurrentDomain` (default 2) but no code reads it. **REMEDIATED (walkthrough 044).**
- **Unused Reddit OAuth path.** `extract/reddit/reddit.go` has `authenticate()` (43-82), `FetchSubredditPosts()` (142-174), and `FetchPostComments()` (176-208) that are never invoked — only the public endpoints are used, and no `ClientID`/`ClientSecret` are configured. ~70 LoC of dead code. **REMEDIATED (walkthrough 044).**
- **Duplicated INSERT OR REPLACE boilerplate.** `runner/crawl.go:114-180`, `runner/reddit.go:97-106`, and `runner/x.go:107-151` each open their own 9-11-line insert block. A shared `writeModel(ctx, table, fields, values)` helper would reduce each site to ~5 lines. **REMEDIATED (walkthrough 044).**
- **Frontier state transition duplication.** `frontier.go:35-46` (`RecoverStale`) is called from `runner/crawl.go:59-63` *and* re-logs what `RecoverStale` already logs. `MarkDone` / `MarkFailed` (`frontier.go:114, 128, 140`) are three near-identical `ExecContext` calls that could collapse into a single `updatePageState(ctx, state, updates)`. **REMEDIATED (walkthrough 044).**
- **Context propagation leak (crash-resume risk).** `runner/crawl.go:117, 127, 137, 149, 166, 179` and `runner/article_writer.go:92, 97, 103` all use `context.Background()` inside the processing loop. Outer-context cancellation (e.g. shutdown) does not reach these calls; writes continue to complete after the crawler has been asked to stop, which undermines the `INFLIGHT`-reset-on-startup invariant in CLAUDE.md. **REMEDIATED (walkthrough 044).**
- **Potential worker leak on shutdown.** `runner/crawl.go:103-105` uses `sem.Acquire(cleanupCtx, MaxConcurrency)` with a 5s timeout; if workers take longer they are not awaited. A `sync.WaitGroup` would wait them out or surface a hang. **REMEDIATED (walkthrough 044).**
- **Silent error swallowing in `PushLinks`.** `frontier.go:166-182` `continue`s on both malformed URLs and DB errors with no categorized metric. Hard to distinguish "bad input" from "infrastructure failure" in ops. **REMEDIATED (walkthrough 044).**
- **Only two runners call `RecoverStale` at startup.** `runner/crawl.go` does; `runner/reddit.go` and `runner/x.go` do not. If the Reddit/X fetcher crashes mid-batch, `INFLIGHT` rows never reset for that source. **REMEDIATED (walkthrough 044).**
- **Comment typo, trivial.** `cmd/civic-ingest/main.go:166` says `"FetchX"`; should read `"Fetch X"`. **REMEDIATED (walkthrough 044).**

### LOC-reduction targets

- `ClaimItems` in `frontier.go:48-110` (62 LoC) can drop to ~35 LoC via single-transaction `UPDATE ... RETURNING` instead of SELECT-then-loop-UPDATE.
- `processPage` in `runner/crawl.go:114-180` (67 LoC): extract robots / fetch / store / extract into helpers; collapse six `MarkFailed` sites into one with error-category tagging. ~35% reduction realistic.

### Test gaps

- `frontier_test.go` covers the happy path but no permanent-failure, retry-backoff, or concurrent-`MarkDone` tests. Frontier is the correctness core — worth 4-5 extra tests.
- Reddit / X `APIClient` is not interface-typed; no mock harness. Adding `internal/fetcher/APIClient` with `Fetch(ctx, params) ([]byte, error)` would enable deterministic tests.

### Recommendations

- **Delete dead code in one PR:** `ArticleRaw`, `RedditComment`, duplicate `CrawlResult`, `MaxConcurrentDomain`, the Reddit OAuth trio (~110 LoC total).
- **Factor a DB-write helper** shared by all three runners.
- **Thread the real `ctx`** through `processPage` and `ArticleWriter` instead of `context.Background()`. This is the only finding in the ingestion layer with a correctness (not aesthetic) impact.
- **Unify startup recovery:** call `RecoverStale` from every runner's `Run()`, or move the call into `Frontier` itself so it cannot be forgotten.

## 2. Analysis Layer — Python (`analysis/src/`, excluding `api/`)

### LLM reasoning pipeline

- **Ollama is returning confidence on the 0-100 scale (live bug).** `analysis/src/llm/ollama.py` post-parse validation rejects ~9% of bot-detection responses with `confidence: value X above maximum 1` (observed 6 failures in first 66 docs on 2026-04-19). When validation fails, `engine/bot.py` falls back to heuristics. Net effect: a sizable fraction of bot rows have heuristic-only confidence while the rest have LLM-self-reported confidence, so the distribution is no longer comparable across rows. **REMEDIATED (walkthrough 045).** Parse-time coercion added in `llm/base.py::_coerce_numeric_scales` (values in (1, 100] divided by 100 with a warning); BOT_SYSTEM_PROMPT + TEXT_ANALYSIS_SYSTEM_PROMPT + CLAIM_EXTRACTION_SYSTEM_PROMPT all carry the "decimals only, not percentages" rule with a worked example; prompt versions bumped.
- **Confidence still uncalibrated.** Carry-over from 04-16 audit. No golden set, so post-hoc calibration is blocked. **OPEN** (deferred — blocks on labeled-data work, not code).
- **Prompt-quality gaps still open.** `TEXT_ANALYSIS_SYSTEM_PROMPT` has no worked examples and no explicit "no verbatim evidence → set confidence < 0.3" guardrail. `BOT_SYSTEM_PROMPT` does not weight signals. **OPEN** (carry-over) — 0-100 guardrail added in walkthrough 045; worked-example work for TEXT_ANALYSIS still pending.
- **Narrative / claim extractors duplicate LLM plumbing.** `engine/claim_extractor.py` and the new `engine/narrative_clusterer.py` each call `get_llm_client()` and parse JSON in slightly different ways from `engine/analyzer.py`. Worth collapsing into a common `run_llm_task(task_type, prompt, schema, text)` helper once a third LLM-driven engine is added (arguably now is the threshold). **OPEN** (refactor, deferred).

### Supporting analysis / ETL code

- **Duplicate `STRONG_CONFIDENCE_THRESHOLD = 0.7`** in `engine/constants.py:10` *and* `reporting/aggregators/constants.py:14`. Only the aggregator copy is imported (`reporting/aggregators/sentiment.py:24`); the engine copy is orphaned. **REMEDIATED (walkthrough 045)** — engine copy dropped; aggregator copy is now the single source of truth.
- **Divergent retry/backoff between LLM backends.** `llm/gemini.py:124` uses exponential backoff (`wait_time = 2 ** attempt`); `llm/ollama.py:131` sleeps flat 1s. Either unify or document the intentional difference. **REMEDIATED (walkthrough 045)** — Ollama now uses the same `(2 ** attempt) + 0.5` backoff.
- **Per-request JSON parsing in hot path.** `reporting/aggregators/sentiment.py` calls `json.loads(output_json)` at lines 165, 244, and 373 — the same row is parsed up to three times per aggregation run. Either carry the parsed dict through the accumulator or push the extraction into SQL via `json_extract(output_json, '$.label')`. For 10k+ rows the cost is noticeable. **REMEDIATED (walkthrough 045)** — sentiment aggregator now parses once per row; see `_fetch_task_rows` consolidation below for the cross-aggregator fix.
- **Duplicated SQL (cutoff vs. no-cutoff).** `reporting/aggregators/sentiment.py:105-118` (sentiment) and `122-135` (favorability) each branch on `cutoff`, repeating the same SELECT twice. Consolidate into `_fetch_task_rows(task_type, cutoff)` — removes ~16 LoC and aligns all aggregators on the same pattern. **REMEDIATED (walkthrough 045)** — `fetch_task_rows` helper added in `aggregators/base.py`; sentiment aggregator migrated.
- **`get_bot_flagged_doc_ids` not cached across aggregators.** `reporting/aggregators/base.py:46-87` is called once per aggregator; `job_runner` now runs 4-6 aggregators per refresh, so the same query runs 4-6 times. Accept an injected `bot_docs` set to avoid this. **REMEDIATED (walkthrough 045)** — sentiment + geo aggregators now accept an injected `bot_docs` set; job_runner computes once per refresh and shares.
- **ETL lookup N+1.** `etl/loader.py:199-201, 247-249, 300-302` — three separate `SELECT doc_id FROM docs WHERE ident = ?` lookups, one per doc. On a 1000-doc batch this is 1000 round-trips. Preload idents into a set once before the loop. **REMEDIATED (walkthrough 045)** — each `_load_*_batch` preloads its source-type's idents once into a Python set.
- **Broad `except Exception` in `engine/analyzer.py:70, 290` and `etl/loader.py:168`.** Silences import/type errors alongside the intended runtime errors. Narrow to specific exception classes and re-raise others. **REMEDIATED (walkthrough 045)** — narrowed to `(ImportError, RuntimeError)` / `(ValueError, RuntimeError, KeyError, TypeError)` / `(OSError, UnicodeError)` respectively; bot.py narrowed too.
- **`_collect_topic_sample` is 12-positional-parameter.** `reporting/aggregators/sentiment.py:215-270`. Ergonomic refactor: accept a single dict or dataclass. **OPEN** (ergonomic, deferred).
- **Aggregators re-parse `output_json` per aggregator run.** System-wide, not just sentiment (`outlet.py`, `bot.py`, `geo.py` follow the same pattern). Same fix as above would propagate. **OPEN** — outlet/bot/narrative/propaganda still parse per-aggregator; the bot_docs injection in walkthrough 045 cuts the cross-aggregator query cost, single-parse-per-row per-aggregator remains.
- **`loader.py` carries three unrelated responsibilities.** ETL (`load_new_raw_content`), read-path lookup (`get_unprocessed_docs`), and AI-output writes (`save_ai_output`). Splitting into `ContentLoader` / `DocStore` / `OutputStore` would make the single-responsibility story cleaner and simplify testing. **OPEN — refactor, not urgent.**
- **Settings sprawl.** `common/settings.py` now holds 25+ fields mixing LLM config, narrative thresholds, and deployment flags. Group into nested config classes (`LlmConfig`, `NarrativeConfig`, `EtlConfig`) when the narrative pipeline stabilizes. **OPEN** (deferred).

### Engine hot-path inefficiencies

- **`engine/analyzer.py:83`** — `text_lower[:pos].split()` inside a loop over GOP keywords. With a 5 KB article and ~100 keywords, the text is split 100 times per inference. Precompute the word-index once. **REMEDIATED (walkthrough 045)** — `_word_offsets` builds a char→word-index map once per inference; `_find_entity_positions` and `_is_keyword_near_entity` now do O(1) lookups.

### Tests

- `test_rich_aggregators` covers sentiment + bot but no narrative aggregator tests yet (per walkthroughs 032-033). **OPEN.**
- No golden-set accuracy harness. **OPEN** (carry-over).

### Recommendations

1. **Fix the Ollama confidence-scale bug** (prompt tightening + parse-time coercion). High-impact, 1-2 hrs of work. See §1 of `04_16_2026.md` for why calibration depends on consistent self-report.
2. **De-dupe `STRONG_CONFIDENCE_THRESHOLD`.** Trivial.
3. **Single JSON parse per row** across aggregators — cache in accumulator, push label/confidence into SQL via `json_extract`.
4. **Consolidate SQL `cutoff` branching** across aggregators (`_fetch_task_rows` helper).
5. **Inject `bot_docs` into aggregators** via `job_runner` to eliminate the 4-6× repeated query.

## 3. API Layer — FastAPI (`analysis/src/api/server.py`)

### Findings

- **`/api/profiles` endpoint (`server.py:176-186`) has no UI caller.** Grep across `ui/src/` for `fetchProfiles` / `/api/profiles` returns zero matches. Either wire it up or delete the endpoint + `outlet_agg.get_outlet_profiles`. **REMEDIATED (walkthrough 045)** — endpoint + `OutletAggregator` wiring removed from server and job_runner; aggregator class left in place for tests.
- **`_get_cached_or_fallback` pattern repeated 4-5 times** across `sentiment`, `profiles`, `bot-activity`, `narratives` handlers. Factor into a `@cached_endpoint(key, transform)` decorator. Saves ~30 LoC and removes the risk of divergent cache-miss behavior. **REMEDIATED (walkthrough 045)** — helper lifted into `analysis/src/api/cache_utils.py::get_cached_or_fallback`; every data-retrieval handler calls through it.
- **`.to_dict()` scattered across handlers.** Every aggregator response is manually `to_dict()`-ed in a lambda. Switching aggregator results to Pydantic response models (and setting `response_model=` on the endpoint) gives free serialization, OpenAPI schema, and validation. **OPEN** (deferred; would require aggregator-model rewrite).
- **`get_geo_sentiment` (`server.py` around line 200) does not use `_get_cached_or_fallback`** — it calls the aggregator live every request. Either cache it like the others or document why live compute is required here. **REMEDIATED (walkthrough 045)** — geo-sentiment now goes through the cache helper and is cached per window by job_runner (already true from walkthrough 041; handler was the last remaining divergence).
- **CORS still `allow_origins=["*"]`** (`server.py:38`, noted as TODO since 04-16 audit). **REMEDIATED** — CORS middleware removed entirely; server docs that the UI is same-origin by design (Vite proxy / Caddy).
- **No auth on review endpoints.** `server.py:235-273` review queue / submit / stats are open; walkthrough 034 acknowledged "future: admin auth" in a comment but didn't gate. Anyone on the LAN can mark golden-set rows. **REMEDIATED** — all `/review/*` endpoints now live on a router with `Depends(require_admin_token)` (CIVIC_ADMIN_TOKEN header).
- **No rate limiting.** `/api/run/analysis`, `/api/run/full-pipeline`, and `/api/run/etl` (all background triggers) can be fired unlimited times, each queuing new background tasks. A single misbehaving client can pile up pipeline runs. **REMEDIATED (walkthrough 045)** — per-endpoint cooldown enforced in `api/dependencies.py::enforce_trigger_cooldown`; configurable via `CIVIC_PIPELINE_TRIGGER_COOLDOWN_SECONDS`; returns 429 with `Retry-After`.
- **Query params unvalidated.** `window` is a free-form string; an invalid value produces garbage cache-miss / live-compute behavior. Use a regex or `Literal["24h", "7d", "30d", "90d"]` type annotation. **REMEDIATED (walkthrough 045)** — `WindowLiteral = Literal["24h", "7d", "30d", "90d"]` enforced on sentiment/narratives/propaganda/geo-sentiment.
- **`/health` doesn't check dependencies.** `server.py:57-64` returns `"status": "ok"` unconditionally. Touch cache/db on startup and expose the result. **REMEDIATED (walkthrough 045)** — `/health` now runs a SQLite `SELECT 1` probe, checks `cache_dir` existence, and returns `status: degraded` if either fails.
- **Stale-cache threshold hardcoded** (`server.py:131`: `STALE_CACHE_WARN_SECONDS = 24 * 60 * 60`). Move to settings. **REMEDIATED (walkthrough 045)** — moved to `settings.stale_cache_warn_seconds` (env: `CIVIC_STALE_CACHE_WARN_SECONDS`).
- **Legacy `process_analysis_queue`** (~40 LoC at the bottom of `server.py`) is still live behind `/api/run/analysis`, despite `job_runner.py` being the preferred path. Either deprecate with a warning log or delete. **REMEDIATED (walkthrough 045)** — deleted; only `/api/v1/run/full-pipeline` and `/api/v1/run/etl` remain.

### Recommendations

1. **Delete `/api/profiles`** or wire a caller.
2. **Decorator-fy** the cache-or-fallback pattern.
3. **Typed response models** — one-shot refactor; gives OpenAPI docs for free.
4. **Gate review endpoints** behind even a shared-secret header before a real auth layer is built.
5. **Lock CORS** per env (dev → `http://localhost:5173`, prod → explicit allowlist).

## 5. Cross-cutting Observations

- **Feature drift with no UI writer.** Two patterns recur: (a) `transformBotData` defined, no caller; (b) `/api/profiles` endpoint live, no caller. Same family as the pre-029 orphan-clustering pattern. Worth a one-line CI check (`ripgrep` for exported-but-unimported symbols in `services/` and handlers with no `fetch*` pair) to catch the next one.
- **Constants replicated across layers.** `STRONG_CONFIDENCE_THRESHOLD` shows up in two Python files; hex colors show up in 4-5 TS files. The project has no shared-constants convention between layers; at minimum pick one place per layer.
- **Pipeline observability gap.** The bot-detection log excerpt from 2026-04-19 shows the Ollama validator rejecting output silently (WARNING + fallback to heuristics). No metric is emitted, so a regression in prompt quality or model behavior shows up only as degraded accuracy, not an alert. Adding a `ai_outputs.fallback_reason` column (or a counter in job_runner) would make this visible.
- **No integration test end-to-end.** Go ingest → Python ETL → API → UI has no smoke test. `test_api.py` covers the middle slice only. An end-to-end harness on a seeded DB would catch schema drift and cache-key drift at the same time.
- **Documentation is healthier than the code.** Walkthroughs 029-036 are thorough and the audit trail is genuinely useful. The gap is enforcement — findings from 04-16 (`_extract_gop_entities`, prompt hardening, schema tightness) are still OPEN here.

## 8. Deep Audit — Narrative Engine

Narrative/claim/citation code was deferred from the first pass (walkthroughs 032, 033, 035). This section lands the missing detail.

Files in scope: `engine/claim_extractor.py`, `engine/citation_extractor.py`, `engine/narrative_clusterer.py`, `reporting/aggregators/narrative.py`, narrative-related prompts in `engine/prompts.py`, schemas in `llm/schemas.py`, orchestration in `scheduler/job_runner.py`, tables from migration `007_audit_and_propagation_tables.sql`.

### Correctness & Traceability

- **Claim-extraction validation is solid.** `claim_extractor.py:50-72` verifies verbatim evidence span (line 68), enforces word-count bounds (4-20 for claim, 3+ for evidence — lines 26-28), and clamps confidence to `[0, 1]` (line 71). This is the pattern `analyzer.py` uses; no fabrication gap. **OK.**
- **Clusterer writes no audit metadata.** `narrative_clusterer.py:311-334` (`_create_narrative`) writes the new row but never records which similarity mode (`jaccard` vs `embedding`), which threshold, or which embedding model produced the anchor. After a threshold change (e.g. 0.65 → 0.70), old narratives are silently anchored to the old semantics with no audit trail. **REMEDIATED (walkthrough 045)** — migration 015 adds `clustering_mode`, `clustering_threshold`, `embedding_model` columns on `narratives`; `_create_narrative` now populates them.
- **Row-level confidence hides per-claim uncertainty.** `job_runner.py:446` pools per-claim confidences as `max(...)`. A doc with claims at `(0.4, 0.4, 0.9)` is stored with row confidence `0.9` — downstream cannot tell that two claims were uncertain. **REMEDIATED (walkthrough 045)** — row confidence is now the mean of per-claim confidences; per-claim array remains in `output_json` as the source of truth.
- **Narrative anchor is ingestion-order-dependent.** `narrative_clusterer.py:166-173` anchors on the first-seen claim. If the canonical phrasing arrives second, Jaccard will drift as new matches accrue to the paraphrase anchor. Design-documented, not a bug, but should be called out in the Methodology panel (UI) so users understand anchor drift.

### Efficiency

- **O(N·M) comparison loop in hot path.** `narrative_clusterer.py:200-226` compares every pending claim against every existing anchor. At 10k claims × 500 anchors = 5M comparisons per run; no vector index. For embedding mode specifically, pre-embed all narrative anchors once at clusterer startup instead of the current lazy-per-claim pattern (line 231/236), which re-embeds anchors repeatedly through a run. **REMEDIATED (walkthrough 045)** — embedding-mode anchors are warmed once per run via `_warm_anchor_embeddings`; the lazy `_anchor_embedding` path remains as a safety net. The O(N·M) cosine loop itself remains (no vector index yet) — still OPEN for that structural fix.
- **Embedding fallbacks counted but not exposed.** `narrative_clusterer.py:144, 184` track `embedding_fallbacks` and log it, but the return dict (line 186-191) doesn't include it. `job_runner` summaries therefore can't surface an Ollama embedding-model regression. **REMEDIATED (walkthrough 045)** — `embedding_fallbacks` now appears in the clusterer run-summary dict.

### Correction to §5 (Cross-cutting)

The earlier section claimed the Ollama heuristic-fallback was silent. **Correction:** `inference_method` is saved on every `ai_outputs` row (`loader.py:381, 423-427`; `bot.py:285, 312, 355, 384`; `job_runner.py:235`), so a fallback row IS distinguishable from an LLM row downstream. Keep the observability note in §5 but scope it to the reason, not the method.

### Correctness — the 0-100 confidence bug, in detail

- **Prompt guardrail missing.** `prompts.py:81-118` (`BOT_SYSTEM_PROMPT`) only declares `"confidence": 0.0-1.0` inside the OUTPUT SCHEMA block (line 114). The RULES section (lines 103-109) never states "decimal in [0.0, 1.0], never a percentage." Qwen-class local models that haven't been post-trained on this exact schema pattern will default to their training-set majority (confidence as percentage) about 10% of the time — matching the observed 6/66 rate. **REMEDIATED (walkthrough 045)** — RULES line 6 now spells out the constraint with a worked example (`0.85`, not `85`); same line added to TEXT_ANALYSIS and CLAIM_EXTRACTION prompts.
- **No parse-time coercion.** `llm/base.py:150-153` rejects outright on `value > schema["maximum"]`. A safe, bounded coercion for the narrow case `1 < v ≤ 100` (divide by 100, log a warning) would recover those rows without being credulous about truly malformed values. **REMEDIATED (walkthrough 045)** — `_coerce_numeric_scales` runs before validation, divides by 100 and logs a warning when the field's schema maximum is 1 and the value lands in (1, 100]; applies to every task (bot / sentiment / favorability / claims).
- **`inference_method='heuristic'` fallback carries no exception detail.** The `except` at `bot.py:355-384` loses the original exception by logging it and re-entering `_heuristic_classify`. A small dataclass field `fallback_reason: Optional[str]` on `BotResult` would let the reason reach `ai_outputs` (either as a dedicated column or embedded in `output_json`). **REMEDIATED (walkthrough 045)** — `BotResult.fallback_reason` added and populated by the bot-detector fallback path; the reason now survives into `output_json` via `to_dict()`.
